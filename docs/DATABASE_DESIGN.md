# PostgreSQL Database Design

## DAS 839 - NoSQL Systems End-Semester Project

## 1. Purpose

PostgreSQL is the common reporting database for all four ETL pipelines:

1.  Apache Pig
2.  Hadoop MapReduce
3.  MongoDB
4.  Apache Hive

The Python controller loads the outputs produced by the selected backend
into PostgreSQL.

PostgreSQL is used for reporting and metadata persistence. It does not
replace the ETL processing performed by the selected backend.

## 2. Database

Database name: `nosql_final_project`

The database contains the following tables:

  Table                 Purpose
  --------------------- -----------------------------------
  `runs`                Execution metadata and run status
  `run_batches`         Per-batch record statistics
  `phase_timings`       Execution phase durations
  `malformed_samples`   Retained malformed examples
  `q1_daily_traffic`    Q1 daily traffic results
  `q2_top_resources`    Q2 top resource results
  `q3_hourly_errors`    Q3 hourly error results

All result tables are associated with a `run_id`.

## 3. Runs Table

Table: `runs`

One row represents one pipeline execution.

  -----------------------------------------------------------------------
  Column                  PostgreSQL type         Description
  ----------------------- ----------------------- -----------------------
  `run_id`                UUID PRIMARY KEY        Unique execution
                                                  identifier

  `pipeline_name`         VARCHAR(30)             Pig, MapReduce, MongoDB
                                                  or Hive

  `batch_size`            BIGINT                  Configured maximum
                                                  batch size

  `status`                VARCHAR(20)             RUNNING, FAILED or
                                                  COMPLETED

  `started_at`            TIMESTAMPTZ             UTC execution start

  `completed_at`          TIMESTAMPTZ NULL        Completion timestamp

  `elapsed_seconds`       DOUBLE PRECISION NULL   Measured execution
                                                  duration

  `total_records`         BIGINT NULL             Total input records

  `total_batches`         BIGINT NULL             Number of non-empty
                                                  batches

  `malformed_count`       BIGINT NULL             Total malformed records

  `average_batch_size`    DOUBLE PRECISION NULL   Average actual batch
                                                  size

  `error_message`         TEXT NULL               Failure details, if
                                                  applicable
  -----------------------------------------------------------------------

The run ID is generated by the Python controller.

A run is marked COMPLETED only after all result rows have been committed
and elapsed runtime has been persisted.

Failed runs must not expose partially loaded query results.

## 4. Run Batches Table

Table: `run_batches`

One row represents one non-empty batch.

  -----------------------------------------------------------------------
  Column                  PostgreSQL type         Description
  ----------------------- ----------------------- -----------------------
  `run_id`                UUID                    References `runs`

  `batch_id`              INTEGER                 Batch identifier

  `record_count`          BIGINT                  Actual number of input
                                                  records in the batch

  `malformed_count`       BIGINT                  Malformed records in
                                                  this batch
  -----------------------------------------------------------------------

Primary key: `(run_id, batch_id)`.

The record count represents the actual number of input records assigned
to the batch, not the configured maximum batch size.

## 5. Phase Timings Table

Table: `phase_timings`

Stores optional phase-level timing measurements for diagnostics.

  -----------------------------------------------------------------------
  Column                  PostgreSQL type         Description
  ----------------------- ----------------------- -----------------------
  `timing_id`             BIGINT GENERATED ALWAYS Timing record
                          AS IDENTITY PRIMARY KEY identifier

  `run_id`                UUID                    References `runs`

  `phase_name`            VARCHAR(50)             Name of measured phase

  `duration_seconds`      DOUBLE PRECISION        Duration in seconds
  -----------------------------------------------------------------------

Phase-level timings are diagnostic. The authoritative benchmark duration
is `runs.elapsed_seconds`, measured using the common runtime boundary.

## 6. Malformed Samples Table

Table: `malformed_samples`

Stores the first 100 malformed examples per run in input order.

  -----------------------------------------------------------------------
  Column                  PostgreSQL type         Description
  ----------------------- ----------------------- -----------------------
  `sample_id`             BIGINT GENERATED ALWAYS Sample identifier
                          AS IDENTITY PRIMARY KEY

  `run_id`                UUID                    References `runs`

  `source_file`           TEXT                    Original input filename

  `record_number`         BIGINT                  Continuous input record
                                                  number

  `reason`                TEXT                    Malformation reason

  `raw_line`              TEXT                    Original line after
                                                  line-terminator removal
  -----------------------------------------------------------------------

The sample limit applies only to retained examples. The total malformed
count must include every malformed record.

## 7. Q1 - Daily Traffic Table

Table: `q1_daily_traffic`

Stores daily request counts and byte totals grouped by date and HTTP
status.

  Column            PostgreSQL type   Description
  ----------------- ----------------- --------------------------------
  `run_id`          UUID              References `runs`
  `batch_id`        INTEGER NULL      Batch ID or NULL for whole-run
  `log_date`        DATE              Request date
  `status_code`     INTEGER           HTTP response status
  `request_count`   BIGINT            Number of requests
  `total_bytes`     BIGINT            Sum of bytes transferred

Logical uniqueness: `(run_id, batch_id, log_date, status_code)`.

## 8. Q2 - Top Resources Table

Table: `q2_top_resources`

Stores requested-resource statistics.

  Column             PostgreSQL type   Description
  ------------------ ----------------- -----------------------------------
  `run_id`           UUID              References `runs`
  `batch_id`         INTEGER NULL      Batch ID or NULL for whole-run
  `resource_path`    TEXT              Exact resource path
  `request_count`    BIGINT            Number of requests
  `total_bytes`      BIGINT            Sum of bytes transferred
  `distinct_hosts`   BIGINT            Number of unique requesting hosts

Logical uniqueness: `(run_id, batch_id, resource_path)`.

Only resources with a non-NULL path are included. Whole-run
distinct-host counts must be calculated across the complete input
dataset.

## 9. Q3 - Hourly Errors Table

Table: `q3_hourly_errors`

Stores hourly traffic and error statistics.

  ------------------------------------------------------------------------
  Column                   PostgreSQL type         Description
  ------------------------ ----------------------- -----------------------
  `run_id`                 UUID                    References `runs`

  `batch_id`               INTEGER NULL            Batch ID or NULL for
                                                   whole-run

  `log_date`               DATE                    Request date

  `log_hour`               INTEGER                 Hour from 0 to 23

  `total_requests`         BIGINT                  All valid requests

  `error_requests`         BIGINT                  Requests with status
                                                   400-599

  `distinct_error_hosts`   BIGINT                  Unique hosts among
                                                   error requests

  `error_rate`             NUMERIC(20,12)          Error requests divided
                                                   by total requests
  ------------------------------------------------------------------------

Logical uniqueness: `(run_id, batch_id, log_date, log_hour)`.

Error rate is a decimal fraction between zero and one. Cross-pipeline
comparisons use an absolute tolerance of `1e-9`.

## 10. Handling NULL Batch IDs

A NULL `batch_id` identifies a whole-run result.

A positive `batch_id` identifies a per-batch result.

Do not use zero or another artificial value to represent whole-run
results.

Because PostgreSQL unique constraints traditionally treat NULL values as
distinct, use separate partial unique indexes for batch-level and
whole-run rows.

Example for Q1:

``` sql
CREATE UNIQUE INDEX uq_q1_batch
ON q1_daily_traffic (run_id, batch_id, log_date, status_code)
WHERE batch_id IS NOT NULL;

CREATE UNIQUE INDEX uq_q1_whole_run
ON q1_daily_traffic (run_id, log_date, status_code)
WHERE batch_id IS NULL;
```

Apply the same pattern to Q2 and Q3 using their respective grouping
columns.

## 11. Transactional Loading

The Python controller is responsible for loading adapter outputs.

For each successful adapter execution:

1.  Validate the adapter exit status.
2.  Validate all required JSONL output files.
3.  Begin a PostgreSQL transaction.
4.  Insert run metadata.
5.  Insert batch statistics.
6.  Insert malformed samples.
7.  Insert all Q1 results.
8.  Insert all Q2 results.
9.  Insert all Q3 results.
10. Commit the transaction.

If any operation fails, roll back the transaction. Do not publish
partial query results.

After the result transaction commits:

1.  Stop the runtime timer.
2.  Persist elapsed seconds in the run metadata.
3.  Mark the run COMPLETED only after elapsed time has been saved.

If the elapsed-time update fails, the run must not be marked COMPLETED.

## 12. Relationships

The intended relationships are:

-   `runs` (1) to (many) `run_batches`
-   `runs` (1) to (many) `phase_timings`
-   `runs` (1) to (many) `malformed_samples`
-   `runs` (1) to (many) `q1_daily_traffic`
-   `runs` (1) to (many) `q2_top_resources`
-   `runs` (1) to (many) `q3_hourly_errors`

Every child table must have a foreign key referencing `runs(run_id)`.

## 13. Reporting Usage

The Streamlit application reads PostgreSQL to display:

-   Run history.
-   Pipeline and batch-size information.
-   Runtime comparisons.
-   Batch statistics.
-   Malformed-record counts.
-   Q1 daily traffic results.
-   Q2 top resources.
-   Q3 hourly error analysis.

For query result views, NULL batch IDs are displayed as `Whole run`.

All four pipelines use the same database schema and reporting queries.
